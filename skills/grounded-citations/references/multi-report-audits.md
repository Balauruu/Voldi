# Multi-report research: evidence merge and final audit

Use for delegated research dossiers, capability comparisons and other syntheses with independently authored reports.

## 1. Establish ownership before retrieval

Assign each worker its canonical findings destination, ledger and retained-extract paths. Use a report file only when the task authorizes one; when a tracker body is canonical, request a complete publishable return and retain supporting evidence separately, because a second report creates competing findings homes. Require source registration during acquisition, substantive quotes, acquisition failures, reading scope and proposed-versus-executed labels. Keep concurrent ledger writes separate; independently assigned small integers are not globally unique.

Require exact tool-output artifacts for live-test claims. Treat vendor documentation as documented capability, installed-schema inspection as compatibility evidence, and saved execution as an observation of the exercised path. None establishes superior performance or exhaustive coverage. When reviews run in parallel, give every reviewer the complete candidate and exact retained evidence paths, request source-bound defects and unique repair targets, and reserve final integration/publication for the coordinator; reviewing an abbreviated return can miss unsupported claims in its worked examples.

For a requested exhaustive canonical-source comparison, define the complete reading set before dispatch and partition it into disjoint source units, including required historical and governing records rather than only mechanism rows. Supply complete canonical bodies/discussions and the relevant candidate sections; require a per-source reading-scope declaration, unread portions or blockers, and source-warranted verdicts with unique repair targets. Reconcile the returned source identities against the required set, then inspect consequential warrants and integrate repairs. Do not certify complete reading from row counts, file acquisition or selected-passage checks; keep that comparison's boundary distinct from upstream repository reinspection and runtime validation.

## 2. Preserve usable evidence

Copy full extracts needed for quotes into the durable research directory before temporary caches disappear. Preserve whether a file is cleaned Markdown, raw response, bounded preview, original document or local-source snapshot; a digest proves integrity of the saved representation, not completeness relative to its original.

Use substantive supporting passages rather than headings or navigation to satisfy quote gates. Retain failed/interstitial retrievals as acquisition records only; an HTTP success containing a bot challenge does not establish provider capability. Quote a probe record as evidence of its exact URL/status/preview, not as a full API manual.

Before attributing a reproduced defect, inspect the retained input, output and assertion against the exact source function; a successful process exit may demonstrate a defect or may contradict the narrative claim. Retain full authored fixtures, relevant settings, source locators and actual results for isolated probes, because lengths and booleans alone may not support exact replay. If original inputs are absent or their results contradict the claimed loss, correct that historical claim. When permitted, exercise a separate explicitly labeled boundary fixture, retaining its full inputs/results without altering prior controls or calling it a replay. For an isolated helper, inspect its decorators, defaults and called dependencies first. When that path is side-effect-free and stdlib-only, extract the inspected function with `ast.parse`, compile only that node and supply its required standard-library globals rather than importing a package that may load models or invoke services. Report helper reproduction separately from pipeline execution or model effectiveness.

## 3. Integrate by URL, not citation number

When combining findings into one citation namespace, create a parent-owned synthesis ledger. Register source URLs obtained from worker retrieval records, then map each report's source IDs to parent IDs by exact retrieved URL. When publishing resource-specific findings as separate canonical bodies, retain each report's namespace and resolve its exact ledger from the explicit handoff or captured verifier command; do not assume every evidence directory uses the same filename. Do not reconstruct URLs from prose or treat nearby documentation as validation of an exact endpoint template.

For each cited synthesis source, find its retained text and run:

```bash
python "$S" --ledger synthesis-ledger.json quote SOURCE_ID --text "EXACT_RETAINED_PASSAGE" --from retained-source.md
```

Select passages that support the integrated claim, not merely any existing quote for that source. Save lineage from synthesis ID to originating report/source ID and retained file. Render the synthesis Sources block with the script.

## 4. Audit after all repairs

Run both modes for every report and the synthesis, recording command, exit code, stdout and stderr:

```bash
python "$S" --ledger report-ledger.json verify report.md --evidence
python "$S" --ledger report-ledger.json verify report.md --strict --evidence
```

Classify failures: missing quotes, unknown IDs, mismatched URL mapping, or intentionally uncited registered sources. Preserve IDs and failed-source history rather than renumbering the dossier to hide warnings. For an uncited-registration-only strict failure, compute `registered_ids - cited_ids` from the actual ledger and final prose, reconcile that set with the retained unused-acquisition inventory, and explain which entries are discovery, supporting or unclaimed records. Confirm that no required finding lost its evidence; do not add token citations or delete registrations merely to force a pass. Report evidence success, the actual nonzero strict result and its acceptance disposition separately under the governing criteria.

Review load-bearing statements in matrices and executive summaries against actual source passages. Require publication corrections to identify the operation, unique original text and exact replacement or insertion; apply them only when the target matches once, because reviewer schemas and body boundaries can differ. Resolve semantic disagreements against the declared evidence, then rerun both gates on the complete repaired body, including retained original scope and final disposition. Recompute character/UTF-8 size from that body and identify earlier counts and review verdicts as pre-correction snapshots rather than current blockers. Retain supporting verification records only in an authorized evidence home; do not manufacture a duplicate narrative report.

If a worker retracts a claimed live test, correct every integrated assertion relying on it. Mark missing execution transcripts unverified; do not substitute documentation for proof that the test ran.

Treat quote membership, claim entailment, source independence, coverage and integration performance as separate verification levels. Mechanical coverage excludes tables and code and includes declared-unverified prose; do not present it as a factual-quality score.

## 5. Deliver through the chosen canonical route

Publish the complete integrated findings and necessary evidence in the task's agreed destination. For a tracker-body handoff, keep substantive context inline and link the supporting sources; use the parent map only as an index. Do not create a reading-order README, duplicate reports or an archive merely to satisfy a package convention.

When a multi-file package is authorized, provide its reading-order README, integrated recommendation, detailed reports, candidate artifacts and final machine audit. Verify archive integrity if delivering an archive, and include the actual final audit rather than a placeholder for a future check. In either form, state what is proposed, documented, inspected, exercised and unresolved; give local relative paths a named base and distinguish them from published URLs. Apply `deliver-work` before claiming delivery complete.
